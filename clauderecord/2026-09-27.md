#### V1.16.0 - 2026-09-27
- **修改类型**：修改（**兼容升级** —— 上层接口签名与语义一字未动）
- **涉及模块**：
  - 硬件驱动层 / `hardware/actuators/block_basic.c`、`hardware/actuators/block_basic.h`
  - 应用层 / `Core/Src/app_freertos.c`（仅 `gripper_task` 上电初始化一段 + 两个宏注释）
- **修改内容**：

  1. **转盘舵机由 TIM3_CH2 的 PWM 舵机改为 UART5 总线上的 STS3032。**

     `block_basic.c` 的 `turntable_write_angle()` 原实现是
     `block_servo_write(TIM_CHANNEL_2, normalize_servo(angle_deg))`，
     即把角度换算成 500~2500µs 的 PWM 比较值写进 TIM3_CH2。现改为：

     | 项 | 旧（PWM） | 新（总线舵机） |
     |---|---|---|
     | 执行器 | TIM3_CH2 的 360° PWM 舵机 | UART5 上的飞特 STS3032 |
     | 下发接口 | `__HAL_TIM_SET_COMPARE(&htim3, …)` | `SCS_WritePosEx(id, pos, speed, acc)` |
     | 角度→输出 | pulse = 500 + 角度/360 × 2000 | pos = 角度/360 × 4095 |
     | 量程 | 500~2500 µs | 0~4095（12 位单圈绝对值 ↔ 0~360°） |

     换算公式放在 `block_basic.c` 的 `turntable_write_angle()` 内，量程常量
     放 `block_basic.h`（规范 §7.3：不在业务逻辑里硬编码魔法数字）：

     ```c
     #define BLOCK_TURNTABLE_SERVO_ID         1u
     #define BLOCK_TURNTABLE_SERVO_POS_MAX    4095u
     #define BLOCK_TURNTABLE_SERVO_SPEED      0u
     #define BLOCK_TURNTABLE_SERVO_ACC        0u
     ```

     五个工位换算后的目标位置：**1 / 820 / 1639 / 2458 / 3277**。

  2. **删除 `block_servo_write()`。** 它是 `turntable_write_angle()` 在工程里
     唯一的调用者，转盘改走总线后即成死代码；留着会触发 `-Wunused-function`。
     `CLAMP_FLOAT` 宏随之在本文件内暂时无使用者（另一处使用点在
     `#if BLOCK_USE_DUAL_ARM` 内，该开关当前为 0），**宏不受该告警约束，故保留**。

  3. **`block_basic.c` 新增 `#include "servo_scs.h"`。** 同层依赖（都是硬件
     驱动层），不违反 CLAUDE.md §5.2.3 —— 那条禁的是**业务层**直接调驱动层。
     `hardware/actuators` 已在 `CMakeLists.txt` 的 `target_include_directories`
     里，无需改构建脚本。

  4. **`gripper_task` 上电初始化不再把 ID1 写到 `STS_CENTER`。**
     `servo_set_pos(SERVO_ID_STS3032, STS_CENTER)`（3330 ≈ 293°）改为
     `Servo_Angle(BLOCK_TURNTABLE_HOME_DEG)`。原因：ID1 现在就是转盘那颗舵机，
     旧写法会让转盘**每次上电先扫到 293°**，且 3330 与转盘五个工位没有任何
     对应关系；`Servo_Angle()` 正是 `block_basic.h` 里为「上电同步转盘软件角度」
     准备的接口，它会同时把 `angle_servo` 置成 HOME。
     `STS_CENTER` 因此变为无调用者，**未删除**，只加注释标明现状（它仍是
     「STS3032 量程中段」的参考值）。

  5. **`block_basic.h` 的文档口径修正。** 文件头第 2、3 条原写「双机械臂
     CH2/CH3」「转盘 CH1」，与实际（CH1/CH3、转盘 CH2）及本次改动都不符，
     一并改准；`BlockBasic_TurntableTo()` 的 `@note` 补上「阻塞式总线收发」
     与「换连续旋转舵机则不能绝对定位」两条约束。

- **影响范围**：

  - `BlockBasic_TurntableTo()` 的**唯一调用者**是 `app/ColorIdentif.c:153`
    的 `TT_RotateByQR()`，运行在 NLF_TASK（4KB 栈）—— 满足 `servo_scs.h`
    要求的「调用任务 ≥1KB 栈余量」。
  - `Servo_Angle()` 的调用者新增 `gripper_task`。**该任务栈是 256 字 = 1KB**
    （`servo_scs.h` 里写的 512 字节是旧值），而它**本来就在调
    `SCS_WritePosEx()`**（`servo_set_pos` 分派），本次只多一层内联调用，
    峰值栈深不变，**无新增风险**。
  - **转盘不再占用任何 TIM 通道。** TIM3 保留 CH1(PB4)/CH4(PB7) 给双机械臂，
    `block_basic.c` 仍通过 `Common_used.h` → `tim.h` 持有 `htim3`。
    附带消掉一处死写：`tim.c` 里 **CH2 本来就没有配置**（只有 CH1/CH4），
    旧代码是在往一个未配置的通道写比较值 —— 那本来就不会有任何输出。
  - 双机械臂路径（`BLOCK_USE_DUAL_ARM`，当前 0）**一行未动**。

- **验证状态**：**未验证**（需上电实测）。建议的判据：

  1. 先把车架空，串口助手接 huart2 看 printf；
  2. 确认总线上有 ID1 —— 可直接调 `SCS_Probe()`（广播 Ping）或
     `SCS_Ping(1)`，不必猜 ID；波特率不对时报警率为 0 且 `SCS_GetLastError()==1`；
  3. 依次 `BlockBasic_TurntableTo(1..5)`，确认停位与五个工位对应、
     且方向未被硬件改反（反了就把位置映射改成 `4095 - pos`）。

- **备注**：

  1. **【已知风险，按要求保留】未加相位偏移，HOME 贴在量程跳变点上。**
     `BLOCK_TURNTABLE_HOME_DEG = 0.1°` → pos ≈ **1**，而单圈绝对值编码器的
     0 与 4095 在物理上是**相邻的同一个点**。这正是 `Core/Src/app_freertos.c`
     的 `STS_CENTER` 注释（V1.10.x 记录）以及 `block_basic.h` 里
     `BLOCK_TURNTABLE_STEP_LIMIT_DEG` 想规避的同一个坑。
     转盘停在此处时手推几度就可能跨端跳变，位置环会把误差算成「差一整圈」。
     本次按用户明确要求**不做偏移**；若实测出现整圈反转，加一个 180° 相位偏移
     把 HOME 挪到量程中段（pos≈2048）即可，改动只在
     `turntable_write_angle()` 一行。**但要注意**：五个工位覆盖整圈，
     加偏移只能改变「哪个工位贴在跳变点附近」，不能让所有工位都远离它 ——
     彻底做法是给舵机做中位校准（`SCS_CalibrationOfs`）。

  2. **本次未处理的两处相邻问题**（不在本次范围内，仅记录）：

     - `block_basic.h` 的 `BLOCK_TURNTABLE_STEP_LIMIT_DEG` /
       `BLOCK_TURNTABLE_STEP_DELAY_MS` 两个宏**全工程零引用**，
       而 `BlockBasic_TurntableTo()` 是一次性下发目标、不分段 —— 这两个宏
       描述的「分段移动以降低走最短路径的风险」逻辑**从未实现**。
     - `Segments`/分段移动若将来要补，应基于**当前实测位置**分段，
       而那需要给 STS3032 加回读（`SCS_FeedBack(1)` + `SCS_ReadPos(-1)`），
       不是按软件记账的 `angle_servo` 分段。

  3. **本次的文档口径来源**：CLAUDE.md §2 的现状表里 `block_basic` 属
     「尚待下沉的业务模块」候选，但它的实际职责（机构换换算 + 下发）与
     硬件驱动层一致，**本次未动它的分层归属**，留待那次下沉时一并决定。
